- Service worker is generated by vite-plugin-pwa (`/sw.js`), registered only via `src/lib/registerSW.ts`; push handlers live in `public/push-sw.js` (imported by the SW) — keeps offline caching and web push in one worker without hand-written caching.
- Shared links are `https://sooz.vercel.app/t/{tiktokId}?by={handle}` and `/p/{postId}` (`src/lib/shareLink.ts`, from any copy of the app). On Vercel, `vercel.json` routes them to `api/preview.ts` (edge function): link-preview robots (WhatsApp, iMessage, Facebook…) get Open Graph tags with the TikTok's preview card / creator / caption — the card is `tt/{id}.jpg` on the `covers` branch (800×420: cover, play button, SOOZ badge), made daily by the refresh workflow with sharp because TikTok doesn't answer Vercel's servers; creator and caption come from the library JSON; tiktok.com/embed/v2 + oEmbed are only a fallback or the post's picture / author / caption; people get a 302 to `/?tiktok=…` or `/post/…`. The app also has `/t/:id` and `/p/:id` routes so the links work on Lovable hosting too. The general preview image is `public/og-image.jpg` (gold logo). Older post links still use the R2 static-HTML copy (`getShareLink`) — Supabase functions serve HTML as text/plain, which crawlers can't rely on.
- Mobile navigation and layout clearance share the CSS bottom-nav height tokens, with a standalone safe-area minimum — keeps installed-app controls above the home indicator without mismatched page spacing.
- Christian TikTok videos play through TikTok's official embed player (`/player/v1/{id}`), which receives taps directly (iPhone only allows sound from a tap inside it); database rows come only from the `tiktok-import` edge function (TikTok oEmbed + faith filter), and For You also shows the hand-curated starter list in `src/data/christianTikTokStarter.ts` directly so it is never empty — TikTok has no topic API and re-hosting creators' videos isn't allowed.
- The home feed is a full-screen snap pager (`src/components/reels`) that only mounts media for slides next to the current one — keeps memory low and swiping smooth on phones.
- Google sign-in uses Lovable Cloud's OAuth broker (`/~oauth/initiate`) on *.lovable.app and Supabase OAuth elsewhere (`src/lib/authProviders.ts`); `AuthListener` finishes the session from the URL hash — the Vercel copy has no broker, so Google only works there if the Supabase Google provider is configured. The Google button only shows where it works (`googleAvailable()` reads Supabase's public `/auth/v1/settings`), so nobody lands on Supabase's raw "provider is not enabled" page.
- Don't add `apple-mobile-web-app-status-bar-style: black-translucent` (or change `theme-color` on navigation): in the installed iPhone app it makes the viewport launch one status-bar height too short, so the bottom nav floats up until the next page change.
- Feed videos reuse a small pool of `<video>` players (`src/lib/videoPool.ts`) that the viewer's first tap "wakes": iPhone Low Power Mode only autoplays players already started by a tap, so reused players keep autoplaying after that.
- The TikTok player box always has the video's exact shape — any other box shape makes TikTok's player pad the video with a blurred copy. TikTok's oEmbed no longer returns sizes, so non-9:16 starter videos carry `size` in `christianTikTokStarter.ts` (read from `tiktok.com/embed/v2/{id}` `videoMeta`); DB rows use their thumbnail size.
- TikTok Low Power Mode autoplay: TikTok players load one slide ahead and every touch in SOOZ posts "play" to them (`src/lib/tiktokPlayers.ts`) — Safari forwards a user gesture through postMessage, and a player once started by a gesture may play by itself later. TikToks are never auto-skipped (owner's request): the player shows as soon as it loads, even if TikTok says "Video currently unavailable".
- SOOZ is dark only (light mode removed at the owner's request); `src/lib/theme.ts` just applies dark.
- Calls (1:1 and group) are a WebRTC mesh per call room (`call:{id}` Realtime channel, `src/contexts/CallContext.tsx`): invites go to `user:{id}` (re-sent until answered, 45s ring), the smaller user id makes each pair's offer, failed links restart ICE. TURN comes from the `turn-credentials` function. Anyone in a call can add people (`addToCall`, the "Add" button → recent chats or search): they're invited into the same room (`invite` with `added: true`), an `add` room message shows them "Ringing…" on every phone and turns a one-to-one call into a group call (`adhoc`, named after the people in it), declines/busy are relayed with `unring`, and offers/answers carry names so late joiners see everyone's name. During a call pop-ups show at the top (`AppToasts`) so they never cover End.
- Realtime: never create two subscriptions with the same channel name — the client returns the existing channel and adding listeners after subscribe throws. Presence is one shared channel (`usePresence`); postgres-changes channels get unique names.
- For You is ranked per viewer like TikTok (owner's request: never the same video again, learn what they like). `src/lib/taste.ts` keeps, on the phone (`sooz-taste-v1`, works signed out): every video shown (`seen`) and interest scores per creator / kind (library `kinds`) / hashtag, learnt from watch time (TikTok player `ended` / `onCurrentTime`, dwell), likes, comments, shares, reposts, follows, profile / caption taps, quick swipes and "Not interested" (Share sheet); scores fade ~1.5%/day. `fetchForYouPage` (`src/services/api/feed.ts`) deals each page from unseen videos by interest + freshness (TikTok id = upload time) + popularity + a little luck, with no creator again within ~5, kinds varied, every 5th TikTok from a new creator and The Power House ("Our church") at least every ~10; seen videos only return when nothing new is left (the feed never ends; repeats get `~cycle` keys). Pages are kept per session so coming back to Home doesn't reshuffle; `resetForYou()` starts afresh. The pool = approved DB rows + `christianTikTokStarter.ts` + `src/data/christianTikTokLibrary.json` (recent videos of trusted Christian creators, from TikTok's public creator embed `tiktok.com/embed/@handle`). The instant start skips anything seen before this launch, and leaving the app saves the upcoming videos.
- The library refreshes daily via `.github/workflows/refresh-christian-tiktoks.yml` (`scripts/refresh-christian-tiktoks.mjs`, no secrets); the app reads it live from raw.githubusercontent.com (repo is public), keeps a copy on the phone, and falls back to the bundled file. Add creators in the JSON's `creators` map (and a category in `kinds`; "Our church" = The Power House International accounts, always included). The feed deals TikToks out one creator at a time (`mixCreators`) for variety.
- SOOZ Live is self-hosted without a media server (`src/lib/liveStream.ts`): a fresh MediaRecorder per ~4s clip (each clip a complete video), uploaded in order, announced on Realtime `live:{id}`, latest clips kept in `live_stream_config.stream_key` (JSON) with `playback_url = sooz-live:{id}`. Uploads get random keys (get-r2-upload-url), so playlist files can't work.
- TikTok comments and post share counts live in SOOZ's own tables (`tiktok_comments`, `post_shares`, migration 20261109090000) — TikTok has no public comments API; the UI degrades gracefully until the migration is applied.
- App updates: the service worker uses registerType "prompt" (skipWaiting off) and every build writes `/version.json`; `src/lib/appUpdate.ts` checks on open/resume/every 30 min and `UpdatePrompt` offers "Update now" (waits for the new worker, SKIP_WAITING, reload). Don't switch back to skipWaiting — an old open page would lose its lazy-loaded screens.
- TikTok's player always draws its own like/comment/share column and author header (no parameter hides them, and it's TikTok's cross-origin page), so on full-screen TikToks a solid dock (`.reel-dock` + `.tiktok-sooz-rail--cover`, flush to the right edge, sized to cover TikTok's column both with and without its play bar) holds SOOZ's heart / comment / share — and every slide (SOOZ posts, landscape TikToks, the loading placeholder) uses the same `.reel-dock` so the design matches everywhere, and TikTok's own name / photo strip (~66px at the top of its player) is hidden by zooming portrait TikToks just enough (at most 20px off each side, so TikTok's play / sound buttons stay on screen) to tuck it under the status bar — the video runs right up under the For You tabs with no shadow, like TikTok (owner's request: no top fade or scrim over TikToks). Only where that can't work (short status bar on a tall screen, wider videos) a plain status-bar-coloured `.tiktok-topband` with a clean edge covers it; its height is 0 otherwise. The heart shows TikTok's like count from the library's `likes` (refreshed daily, ~350 per run) +1 if liked on this phone. Repost is in the Share sheet. Share opens `ShareSheet` (repost, send to a SOOZ chat, copy, WhatsApp); shared links are `/t/{id}?by={handle}` (see Shared links above) and open that TikTok first. Reposts: table `reposts` (migration 20261109120000, applied); Following merges reposts by people you follow.
- Captions show two lines with "more" (TikTok and SOOZ posts); a tap opens the whole caption. The library keeps full captions (up to 600 chars, line breaks kept); the daily refresh fills in cut-off ones from each video's embed page.
- Profiles have Posts / Reposts (everyone) and Saved / Liked (own) tabs (`src/services/api/profileTabs.ts`); tapping a tile opens `ReelsViewer` — Home's full-screen `ReelsFeed` in a portal, opened via `?watch=N` so the phone's back gesture closes it. TikToks have no thumbnails (oEmbed dropped them), so reposted TikToks get caption tiles.
- Admin-only screens (the Christian TikTok manager at `/tiktok`) check `src/lib/admin.ts` by account id — no email addresses in the public repo.
- Messaging is WhatsApp-style (migration 20261109150000, applied): replies, forwards, edits (15 min), delete for me / for everyone (2 days; group admins any time via `admin_delete_message`), reactions, stars, pinned messages (3), polls, voice notes (hold mic: slide left cancels, up locks), photos / videos / documents (Supabase `media` bucket, `chat-files/`), location (OpenStreetMap tiles), contact cards, @mentions, *bold* _italic_ ~strike~ `code` formatting, read ticks from each member's `last_read_at` / `delivered_at` (`mark_chats_delivered()` runs whenever the app is open), typing via broadcast channel `typing:{chatId}` (one shared channel per chat — `src/lib/chatTyping.ts`), per-person archive / pin / mute / unread / favourite / clear / delete in `conversation_participants`, group admins / settings, blocking, disappearing messages (`expires_at` set by trigger, hidden by RLS). The chat list is one RPC (`my_chat_list()`); data access is `src/services/api/chat.ts`. Chats open from the URL (`/chat?c=ID&m=messageId`) at the newest message (a ResizeObserver keeps them there while photos / reactions load, unless the reader scrolled up). Long-presses swallow the finger-lift so it never taps the menu that just opened.
- Supabase sign-in settings (owner-approved): new members are confirmed automatically (`mailer_autoconfirm`) because no email service is set up yet (Supabase's built-in mailer is test-only: 2 emails/hour), so sign-up signs people straight in; email links return to the address they used (`window.location.origin`, with sooz.lovable.app and sooz.vercel.app in Supabase's redirect allow list). Email-code sign-in and password-reset emails still use the built-in mailer until custom SMTP is added. The sign-in email is Supabase's "Magic Link" template, customised (owner-approved) to show the 6-digit code (`{{ .Token }}`, `mailer_otp_length` 6) plus a sign-in button — Supabase's default only had a link. BUT Supabase ignores custom templates on its built-in mailer (changelog 29370), so the code only appears once custom SMTP is connected — until then the email's link signs people in, and the app's code screen offers both. Sign-up also offers "Email code" with just the email: `usernameFromEmail` picks a free username ("joy.adams@…" → `joyadams`, or `joyadams27` if taken) and `nameFromEmail` a display name, sent as sign-up data (`shouldCreateUser`); people can change their username in Edit Profile (checked free with `usernameTaken`, which escapes `_` / `%` for `ilike`).
